## 🚨 P1 Hotfix — Backend Service Restoration

### 症状

- `http://192.168.0.185:8888/` (frontend) からダッシュボードの現場一覧が表示されない
- ユーザー報告: 「サービス立ち上がっていない？」

### 根本原因

`backend/app/core/monitoring.py` (Loop 50 で追加) が `from prometheus_client import Counter, Histogram` を import しているが、**container 内で pip install されていない**。

```
File "/app/app/core/monitoring.py", line 10
    from prometheus_client import Counter, Histogram
ModuleNotFoundError: No module named 'prometheus_client'
```

| 観点                 | 旧設計 (silent failure)                                   | 新設計 (fail fast)                      |
| -------------------- | --------------------------------------------------------- | --------------------------------------- |
| 依存解決タイミング   | container 起動時 `pip install --quiet -e .`               | image build 時 `pip install -e .[dev]`  |
| 依存追加後の必須操作 | container restart (忘れがち)                              | `docker compose build backend` (明示的) |
| 欠落時の挙動         | runtime ImportError → uvicorn 死亡 / compose は `Up` 表示 | image build 失敗                        |
| container 起動時間   | ~45s (pip install を毎回)                                 | ~数秒                                   |
| code 編集 hot-reload | OK (volume mount)                                         | OK (volume mount 維持)                  |

### 修復 (PR #5 merged)

- `backend/Dockerfile` 新規 — image build 時に `pip install -e .[dev]` を実行
- `backend/.dockerignore` 新規 — `__pycache__/` / `.coverage` / `.venv/` 除外
- `docker-compose.yml` — `image: python:3.12-slim` + `command: pip install...` を撤廃、`build: ./backend` + `image: wmcdss-backend:dev` に
- `.gitignore` — `.coverage` / `coverage/` / `htmlcov/` 追加

### 検証

- `docker compose build backend` → `Successfully installed ... prometheus_client-0.25.0 ...`
- `docker compose up -d --force-recreate backend` → `Up 24 seconds (healthy)`
- `curl /readyz` → `{"status":"ready","db":"ok"}`
- `curl /api/v1/sites` → 9 sites returned
- `curl /metrics` → prometheus 形式

### 🧠 Test-infra Patterns 確立 (再利用可能)

1. **Leaflet mock 再注入** (Loop 62 で発見)
   - `vi.clearAllMocks()` 後に `mockL.map.mockReturnValue(mockMap)` を再注入しないと `L.map()` が undefined を返し `.setView` で爆発
   - dashboard.test.tsx の beforeEach パターンを app-shell / etc に移植

2. **InMemoryStorage shim** (Loop 62 で発見)
   - vitest v3.2.4 + jsdom + AppShell `usePersistedState` の組み合わせで `window.localStorage.setItem` が undefined 化する jsdom bug
   - `Object.defineProperty(window, 'localStorage', { value: new InMemoryStorage(), writable: true, configurable: true })` で独自 Storage 注入

3. **vi.advanceTimersByTime + act** (Loop 63, 65 で再利用)
   - SiteRegisterPage 1200ms / ReportsPage 1500ms / SettingsPage 2000ms の setTimeout を時間進行で検証
   - `act(() => vi.advanceTimersByTime(1300))` でステート遷移を待つ

4. **postMessage protocol テスト** (Loop 64 で確立)
   - TweaksPanel の `__activate_edit_mode` / `__deactivate_edit_mode`
   - `await act(async () => { window.dispatchEvent(new MessageEvent('message', { data: {...} })) })` で React state flush

5. **vi.resetModules + dynamic import** (Loop 66 で確立)
   - main.tsx のような **import 時に副作用** がある module を 1 test = 1 fresh state でテスト
   - `vi.resetModules(); vi.doMock(...); await import('../main');` を beforeEach に

6. **pointerdown scrub テスト** (Loop 67 で確立)
   - `Object.defineProperty(el, 'getBoundingClientRect', { value: () => realRect })` で jsdom 0×0 rect を realistic に置換
   - `window.dispatchEvent(new PointerEvent('pointermove', { clientX: X }))` で drag シミュレート
   - `pointerup` で listener detach も検証

7. **DOM 構築は createElement のみ** (Loop 66 で security-lint 対応)
   - `document.body.innerHTML = '<div id="root"></div>'` を `createElement + appendChild` に置換
   - hard-coded 文字列でも XSS pattern として警告される
