## 2. 発見項目

### F1 [P0] 「週間天気予報」が生成データ
証拠: `dashboard.tsx:450-454` が `FORECAST_DAYS` と `generateWeather()` で描画。バックエンドに予報API・forecastsテーブル利用は無い。
影響: 実在しない予報が「予報」として表示され、計画判断の誤用リスク。
修正: 接続時は「予報（サンプル）」表示を明示＋実データの予報カードを非表示に。

### F2 [P1] 判定画面がバックエンド断時に生成データでチェックリスト表示
証拠: `decisions.tsx` は `backendDecision == null` のとき `generateWeather(site.id)` で表示。`live` フラグで判定表示は分けるが、チェック表・養生メモは生成値。
影響: 警告帯を見落としたユーザーが生成値で「作業できる」と誤解する可能性。
修正: `backendConnected() == false` のとき判定画面をブロック。

### F3 [P2] 起動時initFromBackendがログイン前に実行され、401→モック保持
証拠: `main.tsx` がレンダリング前に `initFromBackend()`。バックエンドがJWT必須化されると401→モック表示。ログイン後に再取得しない。
影響: ログイン後もモックデータのまま表示され続ける。
修正: ログイン成功後に `initFromBackend()` を再実行。

### F4 [P1] 現場詳細・気象画面の生成データ混在
証拠: `site-pages.tsx:170-171` は `generateWeather/generateMarine` を無条件使用。`weather-marine.tsx` は接続時null表示に改善済みだが site-pages は未改善。
影响: 実データ欠測時に生成値が表示され、ダッシュボード集計も生成値ベースになる。
修正: site-pages も接続時は生成値を出さない。

### F5 [P2] ロール切替が表示モードと認可を混同
証拠: `app-shell.tsx:206` の `role` は `usePersistedState` で保存される表示モード。認可は `AuthStore.getUser()?.role`（別系統）。
影響: UIは正しく認可側を使うが、表示上のロール切替と混同しやすい。
修正: 表示モード名を「現場/本社ビュー」に変更（軽微・次回改善）。

### F6 [P2] アクセシビリティ未監査・未整備
証拠: aria属性は一部（`role="alert"` 等）あるが、ログイン入力欄に `<label>` 相当なし、フォーカス管理・地図のキーボード操作は未確認。
影響: 高齢従業員・視覚障碍者・キーボード利用者が操作困難。
修正: 入力欄へ `aria-label` 追加（実装済み）。本格a11y監査はPhase 3。

### F7 [P2] PWA未対応
証拠: `manifest.json`・service worker 無し。
影響: 現場スマホ利用でホーム画面追加・オフライン閲覧不可。
修正: 基本manifest+静的アセットSWを追加（実装済み）。

### F8 [P2] localStorage JWT（XSS窃取リスク）
証拠: `auth-token.ts`。
対応: CSP強化済み（nginx）。httpOnly Cookie化はPhase 3。

### F9 [P2] E2EはFirefoxのみ・認証フローE2E無し
証拠: `playwright.config.ts` のprojectはFirefoxのみ。
影響: ブラウザ差・認証回帰を検出できない。
修正: Chromium追加・ログインE2EをPhase 3へ。
