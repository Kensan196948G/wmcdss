# WMCDSS 統合評価（2026-08-12・改善前ベースライン）

## 1. プロジェクト概要

- 名称: Weather-Marine Construction Decision Support System（現場気象海象 自動集計・施工判断支援システム）
- 目的: 建設現場の「今日この現場で工事を進めてよいか」を、気象庁観測値＋現場別しきい値で自動判定し、履歴・監査証跡を残す
- 利用者: 現場担当者、本社管理者、経営層、協力会社（想定600名）
- 技術: FastAPI + SQLAlchemy async + Postgres16 + React19/Vite + nginx + Docker/systemd、AI: Claude API
- 完成段階: MVP RC → 本番運用化 Phase 1 完了（PR #65〜#68）。**本番デプロイ未実施（デプロイ先未確定）**
- 運用段階: 試験運用準備中（実現場1件の計画はあるが実施の証拠なし）

## 3. 総合判定

**条件付き利用可（パイロット限定）**

- 陸上（AMeDAS）ベースの「しきい値判定＋監査」は実用水準に近い
- ただし (1) 海象データ源の破損、(2) 読み取り無認証・RBACなし、(3) 監査アクター匿名化、(4) モック/生成データ混在、(5) GitHub/CI喪失 の5点が本番運用の障害
- 600名全社展開は不可。現場1〜数件のパイロット＋本評価の修正実施後、再度判定するのが妥当

## 4. 強み（20件）

1. 判定エンジンが純粋関数・テスト可能（fail-open防止の設計思想が明確）
2. 観測データはJMA公的データのみ（QCフラグを尊重）
3. 全判定にinputs/thresholdsスナップショットを保存し事後再構成可能
4. 未評価ルールがあるとgoを返さない（安全側設計）
5. 有効期間（active_from/to）とJST暦日の整合
6. 冪等upsert（site_id, observed_at, data_version）で取り込み再実行が安全
7. 起動時セキュリティ検査（fail-closed）と開発用降格フラグの分離
8. APIキー比較にhmac.compare_digest＋長さ上限
9. セキュリティヘッダー（CSP/X-Frame-Options等）をアプリ層とnginxの二重で配信
10. JWT有効期限・AI入力上限・レート制限（本番env）の基本装備
11. テストが異常系・境界値・セキュリティを広くカバー（backend 344/frontend 587/E2E 38）
12. CIにpip-audit/npm auditの脆弱性ゲート
13. Prometheus /metrics と /readyz readiness
14. systemdタイマーPersistent＋取りこぼしcatch-up
15. バックアップスクリプトが世代管理＋--cleanで復元可能な形式
16. 文書が豊富（IT-STAFF/TECHNICAL/SECURITY/STATUS）
17. migrationランナー（版管理付きrepeatable）と本番composeのhealthcheck配線
18. フロントのRBAC受容側（roleクレーム表示制御）が既に実装済み
19. ダークモード・文字密度・レスポンシブ対応
20. AIが無キーでもルールベースで動作（可用性）
