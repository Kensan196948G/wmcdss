| フェーズ | 予測値 | 主要項目 |
|---|---|---|
| 本評価後（Phase 0-1） | **55〜60%** | JWT/RBAC/監査アクター修正、鮮度ガード、モック排除、リストア、監視 |
| Phase 2（3か月） | 65〜70% | ユーザー管理UI、通知（メール/LINE/Teams）、予報取り込み、ETL状態ダッシュボード |
| Phase 3（6〜12か月） | 75〜80% | PWA/オフライン、Entra SSO（対話型）、NOWPHAS海象、Excel帳票、AI評価基盤 |
| Phase 4 | 85〜90% | 協力会社ポータル、モバイル現場操作、予報業務許可取得、センサー連携 |

## 4. 80%到達必須項目
- ユーザー管理+RBAC（現場/本社/経営/協力会社）と監査の完全化
- 予報（48時間先・現場ピンポイント）+通知（警戒・中止の自動発報）
- 海象データの公的・持続可能な供給源（NOWPHAS/JMA）
- バックアップ・リストア・監視・アラートの運用確立（RTO/RPO定義）
- 異常系・欠測時のUI明確化（本評価で一部実施）

## 5. 90%到達項目
- モバイルアプリ/PWA+オフライン同期、協力会社向け限定UI
- AIの根拠引用・信頼度・人間承認ワークフロー・利用量制御
- Entra SSO+HENNGE ONE連携、SharePointレポート連携
- 予報業務許可に基づく正式予報提供

## 6. 意図的に代替しない機能
- 気象予報士による解釈・現場個別の高度判断（KIYOMASA/Weathernewsのコア）→ WMCDSSは「数値基準による透明な判断支援」に特化
- 現地IoTセンサー（ソラテナPro等）→ 導入コストが高く、公共事業の入札要件が明確になるまで保留
- 大規模な気象予測モデルの自社開発 → 一次情報（JMA/NOWPHAS）を利用
